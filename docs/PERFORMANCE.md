# Performance and asset delivery

Measured 2026-09-12 against the installed dependencies and production outputs. Sizes below are bytes, not filesystem block usage. Chunk hashes change between builds. Compression figures are local estimates using Node gzip defaults and Brotli quality 5; they are not measured Cloudflare transfer sizes.

## Generated assets

`npm install` runs `scripts/prepare-assets.mjs`. It replaces generated asset directories before copying current upstream files, preventing dependency upgrades from retaining obsolete bundles. Monaco is copied first, then receives the checked DOMPurify security patch described in [dependency-review.md](dependency-review.md).

| Static directory | Before bytes / files | After bytes / files |
| --- | ---: | ---: |
| `public/monaco/vs` | 39,438,267 / 196 | 24,533,906 / 152 |
| `public/pglite` | 19,601,486 / 132 | 19,527,936 / 15 |
| `public/excalidraw/fonts` | 13,107,068 / 234 | 13,107,068 / 234 |
| Total | 72,146,821 / 562 | 57,168,910 / 401 |

This removes **14,977,911 bytes (20.8%)** from these deployment assets. Deployment size is not the amount downloaded on opening the desktop.

Monaco had stale hashed files from an earlier package version. The current language workers remain available; they are requested when needed. PGlite now includes its core entrypoint, transitive literal imports, and WASM/data files. An Acorn AST walk resolves that closure without executing package code. Unused extension archives, declarations, and alternate entrypoint bundles are omitted. Adding a SQL extension requires explicitly including its runtime assets. Excalidraw's fonts match the upstream package exactly: they are language/font subsets used on demand, including imported scenes with non-Latin text, so they remain intact.

## Cloudflare compression

Do not generate duplicate `.gz` and `.br` files for every asset. Cloudflare negotiates supported response compression with clients; JavaScript, CSS, HTML, and `application/wasm` are among its [supported content types](https://developers.cloudflare.com/speed/optimization/content/compression/). Compression availability depends on response headers and zone configuration. Avoid `Cache-Control: no-transform` when compression is desired.

PGlite `.data` is commonly served as `application/octet-stream`, which is **not** on the documented default compression type list. The deployed raw response had no `Content-Encoding`. Asset preparation therefore creates one targeted gzip level 6 bundle plus a size/SHA-256 manifest: **2,142,456 bytes instead of 6,295,316 bytes (66.0% smaller)** for the data body. These are actual generated bytes, not an assumption about edge compression. The 250-byte manifest and gzip add 2,142,706 bytes to deployment storage; the table above includes them. The original data remains available for compatibility.

SQL Workbench requests this bundle only when opened, verifies bounded lengths and SHA-256, decompresses inside its dedicated worker, and passes the result through PGlite's supported `fsBundle` option. Hosts that apply HTTP `Content-Encoding: gzip` have already decoded the response before JavaScript reads it; that path verifies the raw checksum directly. Other hosts use `DecompressionStream`. Missing, corrupt, unsupported, or timed-out compressed transport falls back to PGlite's original raw asset. This optimization changes delivery only; database snapshots and query execution use the same PGlite engine.

Prefer normal [static asset routing](https://developers.cloudflare.com/workers/static-assets/binding/) for static files. `_headers` applies to [static asset responses](https://developers.cloudflare.com/workers/static-assets/headers/); responses generated by a Worker need their own headers. Hashed build chunks can receive long-lived immutable caching. Fixed-name runtime paths such as `/pglite/index.js` and `/monaco/vs/loader.js` must revalidate or use versioned URLs so dependency updates do not mix incompatible cached files.

## Validation

After pruning, the real-browser integration checks passed for:

- Terminal writes opening in Monaco and surviving reload.
- PGlite queries, imports, persistence, reload, stop, and reconnect.
- Excalidraw image import, scene persistence, and export.

The compressed transport also passed actual workerd/Vite browser tests: query, save, and reload with the raw asset blocked, plus successful raw fallback when gzip is unavailable. Five focused tests cover integrity failures, size bounds, decompression, and HTTP-decoded responses.

The static closure unit tests verify import/URL traversal and omission of extension/declaration files. Those application checks ran on the local Next development server; they do not substitute for testing a deployed Cloudflare build. Re-run the checks after dependency updates, alongside `npm test`, `npm run typecheck`, and the target production build. Measure deployed requests with a clean browser cache before making wire-size or cold-start claims.
